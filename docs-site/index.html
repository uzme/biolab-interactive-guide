BIOLOGY · INTERACTION · OPEN PRACTICE

A practical guide to learning with BioLab.

BioLab Interactive Guide is a visual biotechnology learning platform built around equipment discovery, contextual learning dossiers, and disciplined project collaboration.

01 / QUICK START

Run the project with confidence.

Use the canonical main branch and validate changes before opening a pull request.

TerminalNode.js 22 · pnpm
git clone https://github.com/uzme/biolab-interactive-guide.git
cd biolab-interactive-guide
pnpm install --frozen-lockfile
pnpm run check
pnpm test
pnpm build
pnpm dev

The development server is available through the project’s Vite command. Keep credentials and local environment files out of version control.

02 / LEARNING FLOW

Navigate equipment, not a wall of content.

01

Find a device

Search the catalogue or filter by category to move from a broad topic to a concrete laboratory instrument.

02

Study the dossier

Open the device view to follow its structured 16-stage learning dossier and place the instrument in context.

03

Build a focused set

Use local bookmarks to retain the equipment relevant to your current course, experiment, or review session.

04

Continue offline

Install the progressive web app where supported to keep core learning material available with limited connectivity.

03 / CONTRIBUTION

Improve the guide without losing its clarity.

Focused, reviewable contributions make a learning platform more trustworthy for every learner.

Before you open a pull request

  1. Check existing issues and discussions before proposing substantial work.
  2. Keep one pull request focused on one user-facing improvement.
  3. Run the type check, test suite, and production build locally.
  4. Describe the learner impact and include screenshots for visual changes.
Read the contribution guide ↗
IssuesReport a reproducible problem or suggest a focused improvement. ↗ DiscussionsAsk, share an idea, or begin a design conversation. ↗ Pull requestsReview ongoing, implementation-ready improvements. ↗

04 / SECURITY

Responsible disclosure protects learners and contributors.

Do not publish a suspected vulnerability in a public issue. Instead, contact the repository owner privately with a concise description, affected route or file, reproduction steps, and likely impact. Never include secrets or personal data in a report.
